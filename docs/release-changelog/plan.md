# Plan — A changelog for every release

## 1. `scripts/changelog.mjs`

One file, no dependencies, shelling out to `git` the way `pack.mjs` shells out to `zip`.

**Reading the history.** `git tag -l "v*.*.*"`, parsed as semver and sorted ascending —
not by `creatordate`, which reorders under a rebase. Each released version's range is
`<previous tag>..<tag>`; the version in `package.json` gets `<newest tag>..HEAD`, and is
labelled `unreleased` when no tag of its name exists.

**Reading a range.** `git log --no-merges --format=%H%x1f%s%x1f%b%x1e <range>` — unit
separators between fields and a record separator between commits, so a subject or body
containing a newline cannot split a record.

**Parsing a subject.** `^(\w+)(\([^)]*\))?(!)?: (.+)$`. Then, in order:

1. Strip a trailing `; <version>` — the release-bump suffix (`…viewport; 0.5.3`).
2. Strip a leading `release <version>, with ` / `release <version>: ` off a `chore:`
   subject, keeping the real work that shares the commit.
3. Drop the commit entirely if what remains is only `release <version>`.

**Grouping.** `!` in the subject or `BREAKING CHANGE:` in the body wins over the type.
Otherwise by type, and the sections print in this order:

| Section | Types |
|---|---|
| Breaking changes | any type with `!` / `BREAKING CHANGE:` |
| Added | `feat` |
| Fixed | `fix` |
| Changed | `refactor`, `perf`, `style` |
| Documentation | `docs` |
| Internal | `chore`, `test`, `ci`, `build` |
| Other | anything that does not parse |

Empty sections are omitted. Each entry is `- <subject> (<7-char sha>)`, with a scope
rendered as `**scope:** subject` when one is present.

**Writing.** Keep a Changelog header, versions newest-first, `## [0.6.0] — 2026-08-14`
from the tag's commit date, and a compare link per version against
`https://github.com/thangnm93/SenAnnotate/compare/`.

**`--extract <version>`.** Reads the committed `CHANGELOG.md`, returns the body of that
version's section without the heading, and exits 1 with a message on stderr if the
section is absent or has no entries. This is the mode CI calls, so it must not depend on
anything but the file.

## 2. `package.json`

`"changelog": "node scripts/changelog.mjs"`.

## 3. `CHANGELOG.md`

Generated by running the script, then verified section by section against
`git log <prev>..<tag> --oneline` for all nine tags plus the untagged 0.6.0.

## 4. `.github/workflows/release.yml`

A step between the tag check and `npm ci` — it needs no install, so a missing section
costs seconds:

```yaml
- name: Extract the release notes
  run: |
    TAG="${GITHUB_REF_NAME#v}"
    node scripts/changelog.mjs --extract "$TAG" > release-notes.md
```

The script exits non-zero when the section is missing, which fails the step. Then
`gh release create "$GITHUB_REF_NAME" senannotate-*.zip --notes-file release-notes.md`,
replacing `--generate-notes`. `$GITHUB_REF_NAME` stays an environment variable rather
than a `${{ }}` expression, for the reason the existing tag check documents.

`release-notes.md` is written to the workspace root, where `senannotate-*.zip` also
lives — the glob is `senannotate-*.zip`, so a stray `.md` cannot be picked up as an
asset.

## 5. `CLAUDE.md` and `README.md`

The release procedure gains one line before the commit:

```bash
npm test
# edit "version" in package.json
npm run changelog
git commit -am "chore: release 0.7.0"
git tag v0.7.0 && git push && git push --tags
```

Plus a note in `CLAUDE.md`'s conventions section: the changelog is generated from commit
subjects, so a subject that reads badly ships as a release note that reads badly.

## Verification

No test framework covers `scripts/`, so each of these is run by hand and the output
read:

1. `npm run changelog`, then diff every section against `git log` for its range.
2. `node scripts/changelog.mjs --extract 0.6.0` — prints the section, exit 0.
3. `node scripts/changelog.mjs --extract 9.9.9` — message on stderr, exit 1.
4. Re-run `npm run changelog` — the file is byte-identical (generation is idempotent).
5. Run the new `release.yml` shell locally with `GITHUB_REF_NAME=v0.6.0` set.
6. `npm run typecheck` — unaffected, but confirms nothing else broke.

## Out of scope

Committing the changelog from CI, a lint step on `ci.yml`, and any hand-written notes.
`brief.md` records why.
